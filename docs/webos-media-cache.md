# webOS 媒体缓存策略

针对 Issue #55 的 `media-cache` 累积问题。与 Range/CENC 的 ETag 校验、预取策略和上游接口错误分别处理；不启用整集后台预下载。

## 默认限制

- 磁盘媒体预算 **512 MiB**，包括完成的 MP4 和所有正在下载的预留空间。原来的 512 MiB 只有单文件上限，现在同时限制总量。
- 完成文件闲置 **2 小时**后可删除；超预算优先淘汰最近最少使用的未占用文件。读取、复用和播放释放会更新最近使用时间。
- `.access` 单独记录使用时间，不改 MP4 mtime，保持 HTTP `ETag` / `If-Range` 稳定；记录跨 Service 重启保留。
- 启动清理旧版本相同目录结构的缓存与崩溃留下的 `.mp4.part`。只处理选定缓存根目录下的 `<24 位十六进制 token>/<token>.mp4[.part]` 及 `.access`，不递归删除未知文件或跟随符号链接，不碰账号/历史记录。
- 启动、下载前后、播放切换/释放时检查；普通检查间隔至少 30 秒，运行时每分钟检查。下载按最多 4 MiB 的小块预留空间，数据写入之前检查预算，并发任务共用额度。

## 播放与下载保护

下载任务和 HTTP 响应各持独立引用；响应结束与关闭不会重复释放引用。准备好的源另外保留 2 分钟交接期，覆盖“接口已返回、播放器还没设置源”的间隔。

webOS adapter 经 `POST /api/v1/player/cache-session` 登记当前媒体 token。暂停、缓冲、拖动进度或应用暂时隐藏不释放占用，不能仅凭“现在没有 HTTP 请求”删除缓存。更换/清除视频源与页面退出释放；带会话 ID 和递增 revision 的更新会拒绝迟到的旧集或旧页面请求。Service 重启后页面可重新登记。

当前播放占用不使用闲置超时：电视后台计时器可能暂停，超时会误删仍待恢复的视频。占用在内存中且最多一个；页面重新打开会替换旧会话，Service 重启会清空。因此应用崩溃最多暂留一个文件，不会留下不断增长的永久占用列表。外部自建播放器需要遵循同样会话协议才能获得跨请求保护。

已占用文件不为新下载让位。预算或设备存储不足时返回 HTTP 507 / `MEDIA_CACHE_FULL`，保留当前播放并清理失败下载；缓存初始化失败不阻断找剧等非媒体 API。已有旧文件被占用时可暂超预算，新下载不能继续扩大占用。

Range 索引继续使用独立的 2 项 / 24 MiB 内存预算；淘汰时也避开当前播放与响应使用的索引，不变成完整媒体预取。

## 验证

- `node webos/service/media-cache.test.js`：过期/LRU、旧目录、访问时间持久化、暂停跨 TTL、并发引用/下载、交接期、异常退出残留、未知文件/符号链接、迟到会话。
- `provider.test.js`：真实 HTTP Range / HEAD / If-Range；无活跃 HTTP 流时保护当前文件，在容量清理后继续读取/seek，ETag 不变。
- `range-media.test.js`：重定向后的下载仍检查容量，拒绝时第一块数据不落盘。
- `webos-adapter.test.js`：源设置/移除、连续切集、Service 重启、页面退出与恢复。
- `bash scripts/verify_webos.sh`：上述回归、API/入口及正式/staging 构建检查。测试脚本不进入 IPK。
