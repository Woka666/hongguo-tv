# webOS 有声倍速研究（暂缓接入）

日期：2026-10-26。

这是原型阶段记录。后续已验证批量只取音轨，用户批准在同一 IPK 中加入默认关闭的实验选项。
当前行为和验证边界见 [有声倍速说明](webos-audible-speed.md)，不将本研究的早期取舍当作当前功能状态。
原型基于已发布的 `v0.2.119`（`d6a75e3d8e014d50904e24813cb23cff9aa9044c`）。

## 范围

用户希望参考 [ShirinLiu 的声音方案](https://github.com/aston314/hongguo-tv-releases/issues/57#issuecomment-6400243563)，
仅研究 Web Audio 解码和 WSOLA 保持音调的倍速声音。
现有视频源、Range/CENC 服务、预取和切集机制保留，不引入 MSE 拼接、虚拟集数或全片预下载切集。

评论中的声音端点复用已有整集缓存。评论并未要求单独生成音轨文件，也没有提供可直接合并的补丁。
本原型为适配当前 Range 源，尝试在服务内提取 AAC 为内存中的 audio-only MP4；不写额外音轨文件。

## 已有原型

- `webos/service/audio-media.js`：解析 MP4 音轨采样表，提取 AAC、重写音轨偏移；可读取已有完整缓存。
- `webos/app/webos-wsola.js`、`webos-audio-worker.js`：独立 Worker 做时域变速，保留音调。
- `webos/app/webos-audio-controller.js`、`webos-audio.js`：以现有 HTML5 视频为主时钟，准备完成才切换到独立声音；失败恢复有声 1 倍速。
- 原型含 webOS 构建注入、音频接口、诊断与本地化，全部仅在本研究分支保存。
- 暂停、定位、换源、回到 1 倍速和后台切换会停止或重建声音输出；为 PCM、节点和缓存设置上限。

## 验证记录及边界

2026-10-26 本地执行以下命令，14 项测试全部通过：

```sh
node --test tests/webos-wsola.test.cjs tests/webos-audio-controller.test.cjs tests/webos-audio-media.test.cjs
```

覆盖音调、双声道相位、定位、换源取消、静音、暂停/恢复、后台、错误回退、音频 MP4 结构和本地缓存提取。

Mac Chrome 的隔离页面使用实际 HTML5 video、Worker、OfflineAudioContext 和 AudioContext：
2 倍速时原生声音静音，独立 PCM 有输出；440 Hz/660 Hz 两个样片切换后，实际调度的声音分别保持对应音调。
测试将输出送往分析器后静音，不使用扬声器试听结果作为证据。
FFT 的默认平滑会残留上一音调，不能把单次旧峰值当成仍播放上一集声音的证据。

没有 LG 电视上的有声倍速验证；没有证明现有视频的 `playbackRate` 在所有 webOS 设备都有效。
尚未完成音频端点、生产接入及真实片源长时间播放的完整回归；原型不是发布候选。

## 尚未解决的音频取数成本

真实上游样本的 MP4 索引：

| 项目 | 数值 |
| --- | ---: |
| 完整媒体 | 27,424,404 字节 |
| 音轨时长 | 143.685 秒 |
| AAC 载荷 | 1,150,655 字节 |
| 音频块 | 4,308 |
| 相邻音频块 | 0 |

音频与视频交错。当前 `audio-media.build` 对每块单独读取，最多四路并发，实际源可能产生数千次 Range 请求。
这一实现只能作为格式及信号处理验证，不适合直接用于线上音频准备。

当前成功读取的 `video_model` 没有独立音频地址；不能据此断言所有接口都没有。
初轮多段 Range 请求未取得成功探测结果。后续已验证真实 CDN 批量音轨读取；
新的数据及适用边界见 [音频批量读取研究](webos-audio-range-research.md)。

额外顺序读取当前整集会增加媒体流量和准备时间，用户没有选择承担此成本。
最终采用批量只读音轨，未改变正式 Range 播放、未新增音频的整片视频读取。

## 恢复研究前需解决

1. 确认是否能取得独立音频，或以少量请求读取分散音轨。
2. 明确端到端请求数、额外字节数、准备耗时和取消行为；浏览器取消后服务也应停止无用准备。
3. 在 LG 设备核对视频真实倍速、声音解码、同步、暂停/定位/切集、内存和长时间稳定性。
4. 完成服务与页面接入回归后，再讨论是否采用额外整集读取；需要用户重新确认该成本。

保留 `v0.2.119` 的视频播放与切集机制。功能提交本身不增加发布版本。
