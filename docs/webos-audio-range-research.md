# webOS 有声倍速：音频批量读取验证

2026-10-26，研究分支 `codex/webos-audio-rate`。
这是最初的隔离取数研究。后续用户已批准默认关闭的实验选项，并完成应用接入；
当前状态见 [有声倍速说明](webos-audible-speed.md)。本记录中的数字仍是当时隔离实验的数据。

## #61 的背景

[issue #61](https://github.com/aston314/hongguo-tv-releases/issues/61) 报告 LG OLED65C5PTA、固件 43.21.77、
webOS 0.2.118-test.25 的 1.25/2 倍速画面加速而无声，回到 1 倍速声音恢复。
其参考代码面向完整下载的 MP3、44.1 kHz 单人朗读，混成单声道，在主线程做 WSOLA，
然后以正常速度输出处理后的 PCM。作者明确只有电脑 Chrome 验证，没有 LG 电视实测。

这与 #57 另一位评论者声称电视实测的实现是不同证据，不能混为本应用已有可用补丁。
参考代码没有 MP4 音轨提取、AAC 解码、视频同步、定位/暂停/换集或电视资源验证。

## 对“必须额外读取完整 MP4”的纠正

真实 CDN 已验证多段 Range：同一 HTTP 请求可以返回多个离散音频块。
因此可以在部分片源上只读取音频数据；不必逐块发出数千请求，也不必读取整集视频。

实测数据如下。两次选取的是不同匿名推荐片源，不能将它们直接当成性能优化前后对照。

| 项目 | 串行样本 | 两路并发样本 |
| --- | ---: | ---: |
| 音轨时长 | 204.544 s | 139.947 s |
| 原视频大小 | 5,917,428 B | 3,292,297 B |
| AAC 载荷 | 1,637,579 B | 1,120,843 B |
| 音轨块数 | 6,134 | 4,196 |
| 每个请求的 Range 数上限 | 128 | 128 |
| 批量取音频请求数 | 48 | 33 |
| 批量响应体总量，含各段头部 | 2,244,797 B | 1,535,451 B |
| 取数及处理/核对耗时 | 8,683 ms | 2,620 ms |

时间不包含前置 video_model 解析和 MP4 初始化，也不包含浏览器声音解码。
并发样本另外用原 `range-media._fetchMedia` 单段读取首、中、尾三块，逐字节对照通过；
这三次核对的时间计入 2620ms，但不计入 33 次批量读取及其流量。
两份导出的 audio-only MP4 都由 ffmpeg 完整解码退出 0，无错误日志，并有非零声音能量。

## 浏览器验证

对 204.544 秒的实际提取 AAC 在隔离 Chrome 页面执行：

1. OfflineAudioContext 成功解码，输出双声道、24kHz、204.543958 秒。
2. 本机解码约 249ms；PCM 为 39,272,440 B。
3. 将实际声音交给研究分支原有的 WSOLA Worker，0.75 / 1.25 / 2 倍速各生成 1 秒双声道 PCM，均为有限且非零的数据。
4. 本机各段处理约 13.1 / 7.1 / 2.1ms。

没有输出到扬声器，没有 LG 电视证据，也没有通过此项测试验证真实视频的音画同步或长时间稳定性。
44.1kHz/24kHz 的 440Hz 正弦参考算法测试已单独记录；人声 PCM 的非零能量不能替代音高/听感判断。

## CDN 与校验边界

- 已观察到标准 `multipart/byteranges; boundary=...` 响应。
- 另有 CDN 返回 HTTP 206、`Content-Type: video/mp4`，但响应体包含 multipart；
  部分带开头 CRLF。不能仅凭 Content-Type 错误断言不支持多段 Range。
- 隔离解析器支持从声明或响应体首个边界读取 boundary，并按每段 Content-Range 的精确字节数解析二进制内容。
- `research/webos-audio/multipart.cjs` 是解析研究代码，不是生产网络取数器。
  已测试正常格式、二进制换行、头部边界与体边界、截断、总长变化、重复/额外/缺失范围、额外响应内容等失败情况。
- 完整音轨导出验证使用强 ETag、If-Range，所有批次检查 ETag 不变；收到非 206 的响应立即停止，避免 Range 被忽略后变成整集读取。
- 本轮有候选片源没有强 ETag，被排除。没有证明所有 CDN 都支持多段 Range。
- 每响应最大 1MiB、每请求最多 128 段、最多两路并发，并设网络/整次研究超时。

## 下一阶段接入要求

1. 在研究原型中以批量读取替换 `audio-media.build` 的逐块网络请求，不改变现有视频 Range 路径。
2. 保持现有 CENC 与媒体身份校验；音频不可读取时恢复正常有声 1 倍速，不自动整集下载。
3. 浏览器取消、换集、换速度、退出时中止对应服务端请求；共享准备按消费者计数取消，避免伤及仍在使用的请求。
4. 对编码音轨、解码 PCM、并发、缓存和超时设置上限；已有完整缓存可复用。
5. 用真实服务接口验证音频取数、浏览器解码、暂停、定位、静音和换集，再到 LG 电视核对同步、内存、CPU与声音。
