# webOS #70：单播放器与有限网络预取

0.2.123 的 LG C5 实测报告指出：隐藏预热视频出现时当前集暂停，自动下一集没有接管该视频，取源失败后需要手动重试。本次源码移除该隐藏播放器及其事件转发、DOM 替换模块；主视频始终只有原来的 `hero-video`，恢复稳定播放 5 秒后只做网络预取。

## 取数和取消

- `provider.prepare(..., prefetch=true)` 继续共用已有取源和 Range 索引任务；索引可用即允许前台取回片源，无须等后台预读结束。
- `range-head-cache.js` 缓存经过现有 CENC 处理的开头分块。每块 512 KiB，每源最多 2 MiB，最多两个源，额外缓存总量不超过 4 MiB；按使用时间淘汰，闲置 2 分钟失效。
- 预读总期限 5 秒，逐块读取，不启动解码器，不更新当前播放缓存会话。前台 Range 读取可命中已完成分块或加入同一块在途任务，不重复下载或重复解密。
- 每个等待者独立取消。仅剩后台预取时取消会中止请求；已有前台读者时保留它正在使用的分块。缓存槽在整个读/预取操作期间保持占用，第三个源不能挤掉尚在使用的条目。
- 预读失败保留可用片源，前台读取可以重新请求该块；预取不触发整集下载。强 ETag、Content-Range、CENC 和源身份校验不变。

## 失败恢复

`fetchData` 保留服务错误码和 HTTP 状态。webOS 待播放集的临时取源错误使用现有的一次页面自动刷新预算；它和视频错误后的恢复共用上限。鉴权、参数错误、取消、退出、后台和旧代次均不触发恢复。重试以目标集的待播放位置起播，不能误用旧视频的结尾时间，并保留自动续播诊断标记。Android、MPV、桌面的恢复策略不变。

## 验证

- JavaScript 479 项、Python 42 项、Go 测试与完整 webOS 校验通过。回归包含四次连续自动下一集、真实预取协调器消费、临时错误自动恢复、持续失败上限、退出/后台/账号隔离及缓存容量、过期、取消和并发接手。
- 新构建 IPK 的包结构通过；没有 `webos-media-prefetch.js`，入口仅有一个 video。包内压缩后的 provider 和缓存模块通过 23 项回归，压缩后的 Range 模块通过 HTTP/CENC/重定向/缓存复用测试。
- macOS 无头 Chrome 加载实际 staging 的共享 UI 与 webOS adapter，经本地 HTTP Range 播放 12 秒 H.264/AAC 合成样片：四次自动换集，四集在约 6.35～6.37 秒时均为单 video、未暂停；第二集人为制造预取失败和一次前台取源失败后，无需点击重试即可续播。后续三次续播消费预取结果，页面没有 JS 错误。
- 真实匿名上游有限四个候选的验证中，两个返回 `VIDEO_MODEL_EMPTY`、一个缺强 ETag，均没有放宽校验或后台整集回退。可用候选成功预读 2,097,152 字节；前台准备命中相同片源，两次本地 Range 请求各返回 HTTP 206 / 65,536 字节，额外上游 Range 请求为零。

本次尚未发布新版，也没有 LG C5 的新实机结果。浏览器样片验证不能证明电视上的解码器、音画同步或全部上游片源都已正常。
