# webOS 新版本检查与提示

源码已接入，需随下一次 IPK 发布后使用；已发布的 0.2.117 安装包不会自动获得这项功能。

- 设置中的“检查更新”显示当前版本、检查状态、新版本说明、发布页地址和 webOS Dev Manager 手动安装说明。
- 启动后延迟 5 秒后台检查，恢复前台时也会检查是否已到下一次检查时间；自动检查间隔至少 24 小时，尝试时间持久保存。失败后不连续自动重试，手动按钮始终可重试。
- 播放、后台、文本编辑或弹窗操作期间不显示新版本提醒；回到安全页面后显示一次非模态提示，保持原焦点。同一版本的已提醒记录跨启动保留。
- 无下载、安装或打开安装器能力；不会将 Android APK 或桌面 ZIP 当作 webOS 更新。
- 检查失败明确显示错误，保留上次已知的新版本信息；失败状态跨启动保留，不伪装为“已是最新版本”。设备存储不可用时仍可手动检查，去重退化为本次运行内保存。

## 版本清单与网络

公开下载仓库的 `webos-update.json` 是独立渠道，内容包括应用 ID、平台、版本、webOS 发布页、说明和 IPK 摘要。应用只请求此小型 JSON，不下载 IPK。版本按三个数值分段比较，拒绝错误平台/应用、非法版本、外部或无效发布页、已知版本回退和无效响应。

Service 使用与桌面版一致的内置更新线路：`gh-proxy.com` → `v4.gh-proxy.org` → `gh-proxy.org` → `ghfast.top` → GitHub Raw 直连。每条线路总时限 4 秒（包括重定向），响应上限 64 KiB，仅接受 HTTPS。全失败返回检查失败；没有用户代理设置。

`GET /api/v1/webos/update` 仅返回已校验的版本信息；Service 合并并发检查。浏览器通过现有本机 Service 边界调用，不直接处理外网跨域请求。

## 发布顺序

webOS 工作流先构建、验证并公开 IPK，再运行 `scripts/publish_webos_update.py`。发布脚本确认公开附件的文件名、大小、SHA-256 与本地已验证 IPK 一致，且 Release 已发布，才更新根目录清单。禁止回退到旧版本，也禁止同版本替换不同 IPK；重试时可复用内容一致的已发布 Release。

首次接入可用相同脚本为已有的 0.2.117 IPK 创建清单，不新增安装包或发布标签。后续发版自动维护。

## 验证

- `webos/service/updates.test.js`：版本比较、平台/URL 校验、代理回退与并发、超限/HTML 响应、每日限制、手动检查、失败及提醒持久化。
- `tests/webos-update-notice.test.cjs`：实际设置渲染分支在播放时不提示、恢复后仅一次、焦点保留、其他平台隔离。
- `webos-adapter.test.js` / `service.test.js`：浏览器桥接和真实 HTTP 路由。
- `tests/test_webos_update.py`：IPK 身份、已发布附件一致性、更新渠道顺序及写入隔离。
- `verify_webos.sh` 与 IPK 校验确保前后端模块均进入包，测试代码不进入包。
